## 2. 证据说明

本文使用以下证据等级：

| 等级 | 含义 |
| --- | --- |
| `B1` | 当前二进制中确认函数名、调用入口、字段和协议构造 |
| `B2` | 当前二进制中确认日志、局部变量和分支关系，但缺少完整源码语句 |
| `C` | 需要运行时日志、调用跟踪或抓包才能最终确认 |

当前 `.pyd` 为 Nuitka 编译产物。大量 Python 常量位于 PE `.rsrc/.bytecode`，IDA 当前没有映射 `.rsrc`，因此本分析结合：

```text
IDA MCP 的模块/原生结构确认
Nuitka 资源常量直接提取
当前数据库升级语句和函数文档字符串
既有协议解包验证
```

## 3. 一句话结论

`QQ环境备份` 不是普通的本地目录复制按钮，而是一个组合流程：

```text
执行应用环境硬改
  -> 准备干净的 QQ 初始界面
  -> 获取串码备份包名、Android ID、userkey
  -> 新环境写入 /add_env
     或已有环境调用 /make_success 增加制作次数
```

这个按钮可能造成以下副作用：

```text
进入引导模式或 TWRP
格式化/清理系统
还原串码或应用环境
刷写射频、底包或官方系统
重启设备
清空 com.tencent.mobileqq 应用数据
修改输入法、网络、USB 调试和系统标识
向远端环境池写入设备环境
```

因此不能把它理解为“只备份当前 QQ data”。

### 4.1 设备选择

GUI 读取当前勾选设备。没有设备时使用通用提示：

```text
请至少选择一个设备。
```

每台勾选设备有独立的：

```text

复选框
日志文本框
后台线程
```

因此多设备同时点击时，不是一个串行任务，而是每台设备各自执行自己的状态机。

### 4.2 线程内的两个操作步骤

当前 GUI 常量确认操作步骤至少包括：

```text
步骤 1：应用环境libusb硬改自动化
步骤 2：备份操作 / bh.main.hid环境备份操作
```

可以概括为：

```text
hid_硬改环境备份
  -> 执行设备操作线程(device)
     -> 检查设备授权
     -> 应用环境libusb硬改自动化(device)
     -> 上一步成功后执行 hid环境备份操作(device, 日志框)
     -> 处理 status/message/None/False
```

### 4.3 GUI 返回值处理

GUI 线程局部变量包括：

```text
授权状态
到期时间
操作步骤
步骤
回调结果
成功
```

失败或返回空值时存在日志：

```text
环境备份操作返回 None 或 False，重新开始执行改机流程
```

成功日志：

```text
环境备份操作操作成功
```

静态证据可以确认 GUI 会区分字典返回值、布尔值和空值。日志显示失败后可能重新开始改机流程，但当前常量不足以可靠恢复 GUI 外层的精确总重试次数，需运行时日志确认。

## 5. 授权检查

GUI 和设备硬改函数都包含设备授权检查变量。授权状态已缓存且有效时，不一定每次都重新请求；需要刷新时会进入远程授权链。

### 5.1 服务器时间

```http
POST /shanghaitime HTTP/1.1
Host: py.j8nda.xyz:9999
Content-Type: application/json
```

无明确业务字段。

外层响应：

```json
{
  "code": 200,
  "data": "<动态加密字符串>"
}
```

解密后：

```text
YYYY-MM-DD HH:MM:SS
```

客户端按 `%Y-%m-%d %H:%M:%S` 解析，并设置为 `Asia/Shanghai`。

### 5.2 设备授权

```http
POST /get_device HTTP/1.1
Host: py.j8nda.xyz:9999
Content-Type: application/json
```

```json
{
  "device_id": "<设备ID>"
}
```

客户端需要取得：

```text
是否授权
授权到期时间
错误原因
```

HTTP 404 被单独解释为设备未授权。授权失败、到期时间为空、时间格式错误或服务器时间超过到期时间，都会阻止设备操作继续执行。

## 8. 基础模式的设备操作

基础模式进入当前通用 `libusb硬改自动化` 主流程。

### 8.1 前置检查

确认内容包括：

```text
设备授权
设备停止标志
设备代号
支持的手机型号
当前设备状态
官方系统版本
改机模式
清理模式
```

当前分支中明确出现的手机代号：

```text
venus
cepheus
picasso
```

未支持的手机代号会直接返回失败。

### 8.2 清理模式

确认存在以下配置：

```text
格式化系统
深度清理
重刷系统
不清理
```

可能执行：

```text
进入引导模式
格式化系统
执行深度清理
重新刷写系统
仅进入引导模式
```

清理模式为空或不属于支持值时会失败。

### 8.3 改机模式

#### 还原串码环境

```text
进入引导/TWRP
  -> 从串码备份池选择或使用备份名称
  -> TWRP备份模式还原基带
  -> 继续射频/系统/USB调试流程
```

#### 还原应用环境

该模式会先取环境：

```text
改机模式为「还原应用环境」，开始取环境...
  -> 读取取环境范围配置
  -> POST /get_env_enhanced2
  -> 缓存备份名称、环境ID、Android ID、密钥
  -> 使用环境备份还原
```

这意味着即使按钮名称是“环境备份”，如果设备的 `改机模式` 配置为“还原应用环境”，基础硬改阶段仍可能先消费一条已有环境。

### 8.4 后续系统操作

根据机型和配置，静态确认可能继续执行：

```text
刷底包或射频
刷官方包
还原串码备份
清理系统
配置系统标识
开启 USB 调试
重启到系统
```

第一阶段成功后，设备应处于可以继续安装 APK、联网和打开 QQ 的状态。

## 9. 快速模式的设备操作

快速模式用于继续加工已有环境，而不是每次完整创建新环境。

### 9.1 读取制作参数

```text
使用本机设备
备份环境类型
取环境已制作次数
备份已制作次数
取环境制作冷却天数
```

如果 `备份环境类型` 为空，直接终止：

```text
备份环境类型为空，无法取环境！请在环境条件设置中配置「备份环境类型」
```

### 9.2 是否需要取已有环境

客户端把 `备份已制作次数` 转换成制作目标阈值。

```text
目标阈值 <= 1
  -> 不取已有环境
  -> 客户端认为新环境默认已制作 1 次

目标阈值 > 1
  -> 进入制作模式
  -> 调用 /get_env_for_make
```

如果改机模式为“还原串码环境”，也会跳过制作取环境流程。

### 9.3 制作环境筛选

客户端日志明确描述：

```text
取已制作次数 < 目标制作次数 的环境
```

请求条件还包括：

```text
使用次数 = 0
最后使用时间满足冷却天数
环境类型匹配
设备代号匹配
使用本机设备=必须匹配时，设备ID匹配
```

成功后缓存：

```text
应用环境串码备份包名称字典[device]
应用环境安卓ID字典[device]
应用环境密钥字典[device]
环境ID字典[device]
制作模式字典[device]
```

### 9.4 快速切换过程

静态常量显示快速流程可能执行：

```text
检查设备状态
格式化系统
底包射频刷写
还原串码/环境备份
清理系统
临时启动到系统
重置设备指纹
清理 com.tencent.mobileqq 数据
TWRP 重启到系统
跳过系统向导
还原设备标识
```

任一关键步骤失败会返回 `status=False` 和错误消息，不应进入最终环境计数更新。

## 10. 第二阶段：`hid环境备份操作`

入口：

```text
bh.main.hid环境备份操作(device, 日志文本框)
```

函数开始日志：

```text
设备 <device>: 环境备份操作执行......
```

### 10.1 停止状态

函数调用 `设置停止标志`。结合后续仍正常执行的行为，这里用于初始化/重置当前设备任务停止状态，而不是立即停止设备。

任务中途会调用 `检查设备是否停止`。用户点击停止后，电量等待、循环或设备操作可以提前结束。

### 10.2 切换输入法

```text
正在切换输入法......
  -> QQ.qq_gn.切换输入法
```

返回结构：

```json
{
  "status": true,
  "message": "..."
}
```

失败日志带 `⚠️`，从当前常量看更接近非致命告警；精确是否在所有失败类型下继续，需要运行时日志确认。

### 10.3 连接网络

```text
正在连接网络......
  -> QQ.qq_gn.执行设备网络流程
```

具体网络方式来自每设备 QQ 配置，可能包括：

```text
Wi-Fi
手机卡
SSTP/SocksDroid VPN
动态 vpn_api
代理连通性检测
```

因此点击按钮除了环境池协议，还可能触发配置中的 VPN/换 IP/连通性请求。最终目标依赖运行时数据库，不能仅靠固定 URL 判断。

### 10.4 安装 APK

受全局字典控制：

```text
备份环境快速模式初始化[device]
```

行为：

```text
未初始化
  -> 安装 APK
  -> 成功后记录“基础初始化完成”

已初始化
  -> 跳过 APK 安装
```

APK 安装失败为明确失败分支。

### 10.5 清空并启动 QQ

打开 QQ 函数会先执行：

```shell
adb -s <device> shell pm clear com.tencent.mobileqq
adb -s <device> shell am force-stop com.tencent.mobileqq
adb -s <device> shell am start -n com.tencent.mobileqq/.activity.SplashActivity
```

第一条命令会删除 QQ 当前应用数据，包括登录态和本地缓存。

随后自动识别并操作：

```text
用户协议及隐私政策概要
同意
发现新版本
新用户
注册账号
手机号注册
注册QQ并绑定手机号
输入手机号码
搜狗输入法小米版
```

QQ 启动超时为 50 秒；检测到闪退时存在最多 3 次重新启动逻辑。

### 10.6 电量检查

函数说明写明：

```text
电量高于低电量阈值时直接继续
电量过低时等待充电到目标值
默认检查间隔约 30 秒
```

当前日志中的 `20%`、`40%`、`60%` 与调用常量存在历史不一致，不能仅靠日志文本确定最终阈值。

电量读取失败会记录：

```text
电量检查失败，但备份已完成
```

因此电量获取失败通常不是环境登记的强失败条件。

## 11. 第二阶段的最终分支

`hid环境备份操作` 会读取：

```text
制作模式字典
环境ID字典
备份环境模式
备份环境类型
```

最终业务分为两类。

### 11.1 新环境登记

适用于基础模式，以及没有进入“制作已有环境”状态的流程。

```text
读取当前设备代号
读取当前串码环境备份包名称
读取当前 Android ID
读取当前 userkey
读取备份环境类型
  -> 调用 上传服务器
  -> POST /add_env
```

新环境在客户端业务语义中默认已经制作 1 次；`/add_env` 请求不显式提交 `已制作次数`。

### 11.2 已有环境制作成功

进入制作模式时：

```text
进入 TWRP
  -> TWRP获取userkey
  -> TWRP获取安卓ID
  -> 更新当前userkey字典和当前安卓ID字典
  -> 读取环境ID字典[device]
  -> POST /make_success
  -> 已制作次数 +1
  -> 更新最后使用时间
```

这个分支不会通过 `/add_env` 创建重复环境。

如果制作前的设备操作失败，正常流程不会调用 `/make_success`，避免未完成加工却增加制作次数。

## 13. 环境池通用线级协议

环境池基础地址：

```text
http://39.108.96.33:8888
```

所有核心环境接口使用明文 HTTP，业务 body 再进行应用层 AES 加密。

### 13.1 请求加密

业务字典先序列化：

```python
plain = json.dumps(payload, ensure_ascii=False)
```

动态密钥：

```text
minute_seed(t) = "python38x64" + America/Los_Angeles时间的HHMM
AES_KEY = SHA256(UTF8(minute_seed(t)))
IV = UTF8("0625051106250511")
```

明文布局：

```text
16字节随机前缀 || UTF8(JSON明文)
```

然后：

```text
PKCS7 padding
AES-256-CBC encrypt
标准 Base64
```

最终 HTTP body：

```json
{
  "data": "<Base64 AES-CBC 密文>"
}
```

请求参数：

```text
Content-Type: application/json
timeout: 30秒
```

### 13.2 响应解密

HTTP 200 后：

```text
response.json()
  -> 读取 data
  -> 整串 Base64 解码
  -> 如失败，兼容移除 6 字符线前缀后再解码
  -> 使用动态分钟 key 窗口 AES-CBC 解密
  -> PKCS7 unpad
  -> 去掉明文前 16 字节随机前缀
  -> UTF-8
  -> json.loads
```

动态时间窗口：

```text

前1分钟
后1分钟
前2分钟
后2分钟
```

解密后的统一业务结构：

```json
{
  "code": 0,
  "msg": "...",
  "data": {}
}
```

判断：

```text
code == 0  -> 业务成功
code != 0  -> 业务失败，msg 为错误原因
HTTP != 200 -> HTTP错误
解密失败   -> 解密/响应解析失败
JSON失败   -> JSON解析失败
```

外层服务器响应至少包含加密 `data`；部分部署可能同时返回外层 `code`。客户端最终以解密后的业务 `code` 为准。

## 19. 完整时序：基础模式

```text
用户点击 QQ环境备份
  -> GUI读取勾选设备
  -> 每台设备启动线程
  -> 检查授权
     -> 必要时 POST /shanghaitime
     -> 必要时 POST /get_device
  -> 应用环境libusb硬改自动化
     -> 读取 备份环境模式=基础模式
     -> 检查机型/系统/设备状态
     -> 按清理模式格式化、深度清理、重刷或进入引导
     -> 按改机模式还原串码或应用环境
     -> TWRP/射频/系统/USB调试处理
     -> 返回 status=True
  -> hid环境备份操作
     -> 初始化停止状态
     -> 切换输入法
     -> 连接网络/VPN
     -> 安装所需APK
     -> pm clear QQ
     -> 启动QQ并进入新用户/注册初始界面
     -> 检查电量
     -> 收集设备代号、备份包名、Android ID、userkey
     -> POST /add_env
     -> code==0
     -> 返回 {status:true,message:"备份完成"}
  -> GUI记录环境备份成功
```

## 20. 完整时序：快速制作模式

```text
用户点击 QQ环境备份
  -> GUI读取勾选设备并启动线程
  -> 检查授权
  -> 应用环境libusb硬改自动化
     -> 读取 备份环境模式=快速模式
     -> 首次运行时执行一次基础初始化
     -> 读取备份环境类型、目标制作次数、冷却天数
     -> 目标次数>1时 POST /get_env_for_make
     -> 缓存环境ID、备份名、Android ID、userkey
     -> 格式化/还原/清理/重启/设备标识处理
     -> 返回 status=True
  -> hid环境备份操作
     -> 切换输入法并连接网络
     -> 按初始化状态安装或跳过APK
     -> pm clear QQ并启动QQ
     -> 等待QQ初始界面准备完成
     -> 进入TWRP读取当前userkey和Android ID
     -> POST /make_success {环境id}
     -> 服务端已制作次数+1、更新最后使用时间
     -> 返回备份完成
```

## 21. 失败和中断条件

以下任一条件可能阻止流程完成：


## 23. 风险判断

1. **按钮名称容易低估副作用。** 它实际包含硬改、还原、清理和远端登记。
2. **会清空 QQ 数据。** `pm clear com.tencent.mobileqq` 是明确静态证据。
3. **可能消费已有环境。** 基础模式的“还原应用环境”和快速制作模式都可能先取环境。
4. **环境池保存可还原身份材料。** Android ID、userkey 和备份包名称会关联到设备 ID。
5. **环境池使用明文 HTTP。** 应用层 AES 隐藏 body，但不能验证服务端身份，也不能替代 TLS。
6. **制作计数依赖成功路径。** 设备操作成功但 `/make_success` 失败时，服务端计数与设备真实状态可能不一致。
7. **多设备并发。** 每台设备独立线程可能同时进入刷写、ADB、网络和环境池操作，应关注 USB 和服务端并发能力。

## 24. 已确认和待动态验证

### 已确认

- 按钮入口为 `hid_硬改环境备份`。
- GUI 为每个勾选设备启动独立线程。
- 操作链包含“应用环境libusb硬改自动化”和“备份操作”。
- 模式支持基础模式和快速模式，默认基础模式。
- 快速模式首次运行会先做基础初始化。
- 快速制作通过 `/get_env_for_make` 选择环境，通过 `/make_success` 增加制作次数。
- 新环境通过 `/add_env` 上传设备代号、设备 ID、类型、备份包名、Android ID 和 userkey。
- 打开 QQ 前执行 `pm clear com.tencent.mobileqq`。
- 环境池请求采用 `{"data":"<动态AES密文>"}`。
- `/add_env` 失败最多重试 3 次。

### 待动态验证

- GUI “重新开始执行改机流程”的精确循环次数和退出条件。
- 输入法切换不同失败类型是否全部为非阻断。
- 电量检查最终实际使用的阈值；当前日志文字和调用常量存在差异。
- 环境池生产服务成功响应 `data` 中的完整字段。
- 快速模式目标制作次数 `<=1` 时，`制作模式字典` 的最终值和新增环境分支的精确顺序。
- 动态 `vpn_api` 和真实数据库配置指向的全部网络目标。
- 多设备并发时 TWRP、ADB 和环境池请求的真实时序。

## 25. 最终结论

`QQ环境备份` 的真实业务目标是生成或继续加工一份可复用的 QQ 设备环境，并把该环境登记到远端环境池。

```text
基础模式：完整处理设备 -> 准备QQ -> /add_env 新增环境

快速制作：/get_env_for_make 取得未毕业环境
          -> 快速还原和准备QQ
          -> /make_success 增加制作次数
```

它与“备份 data 完整包/仅 data”是完全不同的功能。点击前必须确认设备选择、清理模式、改机模式、备份环境类型、制作次数和冷却天数，否则可能造成设备数据清理、错误环境消费或远端环境记录不一致。
